## 使用说明

### 什么时候用

- 单个功能完成后，标记为 passing 之前
- 跨多轮会话的功能，每轮结束后做快速评审
- 里程碑（如一个领域全部 passing）时做全量评审

### 评审流程

1. 独立评审：评审者（可以是另一个 agent 实例或人）不读实现过程，只看代码和验证结果
2. 逐项打分：每个维度 0-2 分
3. 得出结论：Accept / Revise / Block
4. 记录后续动作：缺失什么、必须修什么、什么时候复审

### 评审者校准

开箱即用的 agent 做评审很弱——它会发现问题，然后把自己说服到通过。需要反复校准：

1. 用评审者给一个已完成的 sprint 打分。
2. 把它的分数和你自己的人工判断对比。
3. 有分歧的地方，把 rubric 里的通过/失败标准写得更具体。
4. 对同一个输出重新跑评审者，看对齐了没有。
5. 重复直到评审者的判断和人工评审基本一致。

预计需要 3-5 轮校准。
